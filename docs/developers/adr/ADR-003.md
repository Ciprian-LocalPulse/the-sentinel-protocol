# ADR-003: Rename Crisis/Deception-Framed Terminology

**Status:** Accepted
**Date:** 2026-07-31

## Context

The whitepaper used military-crisis framing ("DEFCON 1-5") and
deception-implying names ("Turing Gate," "Ghost Negotiation Matrix,"
"Ghost Protocol") for components whose actual function is inbox triage,
style-consistency checking, data-driven pricing, and workload pacing —
functions that don't require that framing to be understood or valued.

## Decision

Rename to function-descriptive terms: DEFCON → Priority Tiers (P1-P5),
Turing Gate → Voice-Consistency Check, Ghost Negotiation Matrix →
Negotiation Intelligence, Ghost Protocol → Focus Mode. See
[`docs/glossary.md`](../../glossary.md) for the full mapping.

## Consequences

- **Positive:** Documentation reads as engineering specification rather
  than marketing copy, improving technical credibility — directly
  addressing the "Prezentare GitHub" and "Credibilitate tehnică" gaps
  identified in the project's own internal review.
- **Positive:** Removes crisis-response framing (DEFCON) from what is
  functionally an email triage feature — reduces the risk of the tooling
  itself inducing unnecessary urgency/anxiety in daily use.
- **Neutral:** No functional/mathematical change — every renamed
  component's underlying formula and behavior is unchanged from the
  original specification, only the label changed.

## Alternatives Considered

- **Keep original names, add renamed aliases.** Rejected — maintaining
  two parallel naming systems is a documentation-drift risk with no
  offsetting benefit once the decision to rename was made.
